## Project brief for Manus AI

**Project title:** CampusMate — AI Smart Campus Assistant

**One-line description:** Build a responsive web-based AI chat assistant that helps students instantly find information about classrooms, labs, events, campus facilities, and student services.

**Goal:** Create a working prototype where a student types a natural-language question and receives an accurate, helpful answer based only on a predefined campus knowledge base.

**Target users:** Students, visitors, and campus staff.

**Core value:** Reduce time spent searching notice boards, asking staff, or navigating multiple pages for routine campus information.

Campus assistants commonly answer questions on class schedules, library hours, dining, events, facilities, and administrative procedures; a retrieval-based chatbot over structured campus data is a proven, practical approach. [github](https://github.com/csmp2408/Smart-Campus-Assistant)

## What to build

Build a **single-page Streamlit web application** with:

- A chat-style interface
- A campus knowledge base stored in a JSON file
- Natural-language question handling
- Intent detection using keywords and optional LLM support
- Answers for classrooms, labs, events, facilities, and services
- Quick-action suggestion chips
- A “not found” fallback that guides users to available categories
- A clean, modern UI suitable for a project demonstration

For the prototype, prioritize **fast, reliable, offline-capable keyword matching**. Add an LLM only if an API key is available; the app must still work without it.

## Functional requirements

The assistant must support these query categories:

| Category | Example user query | Expected response |
|---|---|---|
| Classrooms | “Where is Room C-204?” | Building, floor, nearby landmark, current timetable if available |
| Labs | “Is the AI Lab available now?” | Lab name, location, timings, capacity, booking/contact details |
| Events | “What events are happening today?” | Event name, time, venue, organizer, registration link if present |
| Facilities | “Where is the library?” | Location, timings, services, contact information |
| Services | “How do I get a bonafide certificate?” | Steps, office location, documents needed, timing |
| Contacts | “Who do I contact for hostel issues?” | Department, person/office, phone/email, working hours |
| Navigation | “How do I reach the auditorium?” | Building, floor, landmarks, optional map link |
| General fallback | “What is the admission fee?” | Politely state that this information is not in the prototype knowledge base |

## Recommended architecture

```text
Student question
      ↓
Streamlit chat interface
      ↓
Query preprocessing
      ↓
Intent / category detection
      ↓
Keyword + fuzzy search over campus_data.json
      ↓
Relevant record selection
      ↓
Response formatter
      ↓
Answer displayed in chat
```

For a stronger version, use this RAG-style flow:

```text
Student question
      ↓
Embedding / semantic search
      ↓
Retrieve top campus records
      ↓
LLM generates grounded answer
      ↓
Answer with source/category shown
```

RAG systems retrieve relevant knowledge-base content and use it to generate an answer, which helps keep responses grounded in the provided campus data. [arxiv](https://arxiv.org/html/2501.13880)

## Tech stack

Use this simple stack:

| Layer | Recommended tool | Why |
|---|---|---|
| Frontend | Streamlit | Fast chat UI, minimal coding |
| Backend/logic | Python | Easy data handling and search |
| Data | JSON | Easy to edit, demo, and extend |
| Search | Python keyword matching + `difflib` | Works offline and is easy to explain |
| Optional AI | Google Gemini API or OpenAI API | Natural-language responses |
| Optional semantic search | Sentence Transformers + FAISS/ChromaDB | Better matching for varied questions |
| Deployment | Streamlit Community Cloud or local run | Quick demonstration |

A production-like campus assistant can use RAG with a vector database and LLM, but for a 2-hour prototype, structured JSON plus keyword/fuzzy search is the safest approach. [github](https://github.com/sizwinz/campus-assistant/blob/master/README.md)

## Core logic

### Query handling

1. Convert the question to lowercase.
2. Remove extra spaces and punctuation.
3. Detect category using keywords:
   - Classroom: “classroom”, “room”, “lecture”, “free room”
   - Lab: “lab”, “laboratory”, “computer lab”, “AI lab”
   - Event: “event”, “fest”, “seminar”, “workshop”, “today”
   - Facility: “library”, “canteen”, “gym”, “auditorium”, “sports”
   - Service: “bonafide”, “certificate”, “ID card”, “hostel”, “transport”, “fees”
4. Search matching records using keyword overlap and fuzzy matching.
5. Select the best record.
6. Format a clear response.
7. If confidence is low, show related options or a fallback message.

### Example response

**User:** “Where is the AI Lab?”

**CampusMate:**  
**Artificial Intelligence Lab** is located in the **Computer Science Block, 3rd Floor, Room CS-301**.  
- Capacity: 40 students  
- Available systems: 35  
- Timings: 9:00 AM – 5:00 PM  
- Booking: Contact the CS Department office  
- Email: ai.lab@college.edu
